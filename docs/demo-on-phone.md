# Демо на телефоне (тестовые данные)

Приложение ставится на телефон как PWA только с адреса `https://`. Поэтому запускаем его на своём компьютере и открываем наружу временной ссылкой. **Только тестовые данные**: для демо отключена обязательная 2FA руководства, пароли простые.

## Что нужно на компьютере
Node 22, pnpm 10 (`corepack enable`), PostgreSQL 16, LibreOffice Writer (для PDF, по желанию), `cloudflared` (https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) или ngrok.

## Шаги
1. `git clone`, затем `git checkout claude/festive-hopper-hoh3uc`.
2. Создайте базу: `createdb hemcenter_demo` (или задайте свой `DATABASE_URL`; по умолчанию `postgresql://hemcenter:hemcenter@localhost:5432/hemcenter_demo`, роль `hemcenter` с паролем `hemcenter` должна существовать).
3. `scripts/demo.sh`. Скрипт ставит зависимости, собирает, применяет миграции, создаёт демо-данные и запускает API (порт 4000) и веб (порт 3000). Остановка: `scripts/demo.sh stop`.
4. В другом окне: `cloudflared tunnel --url http://localhost:3000`. Он напечатает ссылку вида `https://….trycloudflare.com`.
5. Откройте ссылку на телефоне.
   - Android, Chrome: меню → «Установить приложение».
   - iPhone, Safari: «Поделиться» → «На экран Домой»; push работает с iOS 16.4 и только из установленного приложения.
   - Откройте установленное приложение и нажмите «Включить уведомления».

## Логины (пароль у всех `Demo-pass-123`)
| Логин | Роль |
|---|---|
| `demo-admin` | администратор |
| `director` | руководство |
| `manager` | руководитель проекта |
| `secretary` | секретарь |
| `anna`, `boris` | сотрудники |

Для проверки чата войдите на телефоне как `anna`, а на компьютере в другом браузере как `boris`. В демо уже есть проект «Реестр поставщиков» с командой и этапами, чат с решением и задачей, личный чат и служебная записка на согласовании у `manager`.

## Заметки
- Ссылка бесплатного туннеля меняется при каждом запуске, а установленное приложение привязано к старой. После перезапуска туннеля удалите значок и установите заново.
- Ключи Web Push создаются один раз и хранятся в `.demo/vapid.env`.
- Для реальных данных так не делать: они должны храниться на сервере в Казахстане (см. `docs/operations.md`).
