# Инструкция по эксплуатации

Для ИТ-специалиста центра. Система тестировалась на тестовых данных; до работы с настоящими данными сотрудников её нужно перенести на сервер в Казахстане (закон №94-V, ст. 12) и пройти список в конце документа.

> **Что проверено, а что нет.** Резервное копирование, восстановление и нагрузка проверены на этой разработческой машине (результаты ниже). Docker-образы и `docker-compose.yml` **не собирались и не запускались**: в среде разработки нет Docker. Первый запуск на сервере нужно сделать под наблюдением и пройти раздел «Приёмка установки».

## 1. Что нужно

- Сервер в Казахстане: 4 ядра, 8 ГБ памяти, 100 ГБ диска (на 50 человек за год вложения занимают десятки гигабайт; см. раздел 6), Ubuntu 22.04/24.04 или аналог.
- Docker и Docker Compose.
- Домен (например `hem.example.kz`) с записью DNS на сервер. Порты 80 и 443 открыты; HTTPS Caddy получает сам.
- Второй сервер или хранилище **тоже в Казахстане** для копий резервных архивов.

## 2. Первая установка

```bash
git clone <репозиторий> /opt/hemcenter && cd /opt/hemcenter
cp infra/.env.example infra/.env
chmod 600 infra/.env
```

Заполните `infra/.env`:

| Переменная | Что это |
|---|---|
| `DB_PASSWORD` | пароль базы данных: `openssl rand -base64 24` |
| `JWT_SECRET` | 32+ случайных символов: `openssl rand -base64 48` |
| `TOTP_KEY` | ключ шифрования секретов 2FA. **Потеряете — у всех сломается двухфакторная защита.** Копия в сейф |
| `DOMAIN` | ваш домен |
| `VAPID_*` | ключи Web Push: `docker compose -f infra/docker-compose.yml --env-file infra/.env run --rm api node_modules/.bin/web-push generate-vapid-keys` |
| `ORG_NAME_RU`, `ORG_NAME_KK` | название организации в шапке документов |

Парольная фраза для резервных копий:

```bash
openssl rand -base64 32 > infra/backup.pass && chmod 600 infra/backup.pass
```

**Запишите её отдельно и положите в сейф.** Без неё архивы не открыть.

Запуск:

```bash
docker compose -f infra/docker-compose.yml --env-file infra/.env up -d --build
docker compose -f infra/docker-compose.yml --env-file infra/.env exec api sh -c "cd /repo/apps/api && node_modules/.bin/tsx src/cli/create-admin.ts"
```

Последняя команда создаёт администратора и печатает одноразовый пароль. При первом входе система потребует сменить пароль и **включить двухфакторную защиту** (она обязательна для администратора и руководства).

**Создайте минимум двух администраторов**: если единственный потеряет телефон с аутентификатором, второй сбросит ему 2FA в разделе «Пользователи».

### Приёмка установки

1. Откройте `https://ваш-домен`: замок в адресной строке, страница входа.
2. Войдите администратором, включите 2FA, создайте сотрудника, активируйте его по ссылке, войдите им с телефона.
3. «Профиль» → «Включить уведомления» на телефоне; напишите сообщение с другого аккаунта при закрытом приложении: должно прийти уведомление. **Это нужно проверить на реальных Android и iPhone** (на iPhone приложение сначала добавляют на экран «Домой»).
4. «Документы» → создайте служебную записку → «Скачать PDF»: файл открывается (это проверяет связку с Gotenberg).
5. «Состояние системы»: база работает, свободного места достаточно, push включён.
6. Сделайте резервную копию и проверьте восстановление (раздел 4).

## 3. Обновление

```bash
cd /opt/hemcenter
docker compose -f infra/docker-compose.yml --env-file infra/.env --profile tools run --rm backup   # копия перед любым обновлением
git pull
docker compose -f infra/docker-compose.yml --env-file infra/.env up -d --build
```

Миграции базы применяются сами при старте `api`. Откат: вернуть прежнюю версию кода и, если миграции менялись, восстановить базу из копии (раздел 4).

## 4. Резервные копии

Копия содержит базу данных и все файлы (вложения, шаблоны, сканы), упакованные вместе и **зашифрованные** (AES-256), с контрольными суммами. Расчёт строк по всем таблицам внутри копии позволяет проверить восстановление.

### Ежедневная копия

```bash
# вручную
docker compose -f infra/docker-compose.yml --env-file infra/.env --profile tools run --rm backup
# по расписанию: crontab -e
0 2 * * *  cd /opt/hemcenter && docker compose -f infra/docker-compose.yml --env-file infra/.env --profile tools run --rm backup >> /var/log/hemcenter-backup.log 2>&1
```

Архивы лежат в `infra/backups/` (или в `BACKUP_HOST_DIR`). Хранятся 30 дней (`BACKUP_KEEP_DAYS`), семь последних не удаляются никогда.

### Копия на другой сервер (обязательно)

Копия на том же диске не защищает от поломки диска и пожара. Каждую ночь после копирования отправляйте архивы на второй сервер **в Казахстане**:

```bash
rsync -a --ignore-existing /opt/hemcenter/infra/backups/ backup@second-server:/srv/hemcenter-backups/
```

Парольная фраза с архивами не хранится: на втором сервере архивы бесполезны без неё.

### Проверка восстановления («учения») — раз в месяц

```bash
docker compose -f infra/docker-compose.yml --env-file infra/.env --profile tools run --rm --entrypoint /scripts/verify-restore.sh backup /backups/hemcenter-ГГГГММДД-ЧЧММСС.tar.gpg
```

Скрипт открывает копию во временной базе, сверяет число строк каждой таблицы и число и размер файлов с тем, что было записано при копировании, и удаляет временное. Успех: `RESTORE CHECK PASSED`. **Копия, из которой ни разу не восстанавливались, считается несуществующей.** Записывайте результат в журнал.

### Восстановление после аварии

1. Поднимите чистую установку (раздел 2) на новом сервере, не создавая сотрудников.
2. Положите архив в `infra/backups/` и парольную фразу в `infra/backup.pass`.
3. Остановите `api`: `docker compose ... stop api web`.
4. `docker compose ... --profile tools run --rm -e CONFIRM_OVERWRITE=yes restore /backups/hemcenter-....tar.gpg`
5. Запустите: `docker compose ... up -d`. Войдите, проверьте последние сообщения и документы.

Скрипт сначала проверяет архив (контрольные суммы, шифрование) и только потом меняет данные; повреждённый архив или неверная парольная фраза отклоняются, ничего не затрагивая.

### Что проверено

Самопроверка `infra/backup/test-backup.sh` на базе разработки (36 таблиц, 272 файла, около 36 тысяч строк): копия создаётся; без ключа не читается; в папке нет открытых дампов; восстановление во временную базу совпадает до строки и байта; повреждённый архив отклоняется (и по контрольной сумме, и по целостности шифра); неверная парольная фраза отклоняется; перезапись непустой базы требует подтверждения; старые архивы удаляются, семь последних и свежие остаются. Проверка ловит и поломку: если из восстановления убрать файлы, она падает.

## 5. Нагрузочный тест

Скрипт `apps/api/scripts/loadtest.ts`: заводит N сотрудников, подключает их по WebSocket к одной групповой беседе, каждый пишет раз в несколько секунд; измеряет время от отправки до появления сообщения на экранах остальных и проверяет, что ничего не потеряно.

```bash
cd apps/api && BASE=http://localhost:4000 USERS=50 DURATION_S=60 RATE_MS=2000 npx tsx scripts/loadtest.ts
```

Запускать только на тестовой базе (скрипт создаёт временных сотрудников).

| Сценарий (машина разработки, API и база на одной машине) | Доставлено | Доставка сообщения, p95 / макс. |
|---|---|---|
| 50 человек, сообщение раз в 2 с, 40 с, напрямую в API | 49 550 из 49 550 | 23 мс / 42 мс |
| 100 человек, сообщение раз в секунду, 30 с, через веб-сервер | 274 200 из 274 200 | 280 мс / 608 мс |

Требование ТЗ: 50 человек одновременно, доставка быстрее секунды. Выполнено с запасом. **Повторите тест на боевом сервере** после установки: сетевые условия и железо другие.

## 6. Место на диске и мониторинг

- «Состояние системы» (раздел администратора): база, место на диске, число и размер вложений, число устройств для push, заблокированные входом сотрудники. При свободном месте меньше 20 % показывается предупреждение, меньше 10 % — тревога.
- Следите также снаружи: ответ `https://ваш-домен/api/health` должен быть `{"status":"ok"}` (подойдёт любой сервис проверки доступности, находящийся в Казахстане).
- Размер вложений ограничен 25 МБ на файл (`MAX_UPLOAD_MB`). Автоматического удаления старых вложений нет (решение — в `decisions-needed.md`, п. 20).

## 7. Если что-то случилось

| Ситуация | Что делать |
|---|---|
| Единственный администратор потерял телефон с 2FA | другой администратор: «Пользователи» → «Сбросить 2FA». Если администратор один: `docker compose ... exec api sh -c "cd /repo/apps/api && ADMIN_LOGIN=admin2 node_modules/.bin/tsx src/cli/create-admin.ts"` создаёт нового администратора с одноразовым паролем |
| Потерян `TOTP_KEY` | двухфакторные секреты не расшифровать; у всех сбросить 2FA (администраторы входят после повторной настройки) |
| Сотрудник не получает push | проверить «Профиль» → уведомления на его устройстве; на iPhone приложение должно быть на экране «Домой»; телефоны без служб Google (часть Huawei) push могут не получать |
| Не создаётся PDF | Word-файл скачивается в любом случае; проверить `docker compose ... logs gotenberg api` |
| Утечка данных | уведомить ответственного за ПДн; по закону в срок, указанный в политике центра (в ТЗ — 1 рабочий день); журнал аудита (администратор) и CSV-экспорт помогут установить, кто что делал |
| Диск заполняется | «Состояние системы»; расширить диск; сделать копию и убедиться, что она не растёт аварийно |
