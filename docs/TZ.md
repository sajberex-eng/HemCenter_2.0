## 1. Общие сведения

### 1.1. Назначение

Система заменяет рабочие группы WhatsApp собственным защищённым приложением. В нём:

- сотрудники АУП общаются так же просто, как в мессенджере, с любого телефона и компьютера;
- задачи обсуждаются в чате, а решения фиксируются с подтверждением участников;
- протоколы совещаний, приказы и другие формальные документы формируются из обсуждений по шаблонам центра;
- по каждому проекту, задаче и поручению видны ответственный, срок и ход исполнения;
- видно, кто из сотрудников в каких проектах занят и насколько загружен.

### 1.2. Проблемы, которые решает система

| Проблема | Решение в системе |
|---|---|
| Непонятно, кто за что отвечает | Обязательный единственный ответственный у задачи и поручения; матрица «сотрудник × проект»; поиск «кто отвечает за…» |
| Одни и те же сотрудники в нескольких проектах | Профиль загрузки сотрудника; % занятости в проектах; предупреждение о перегрузке |
| Общение в WhatsApp: решения теряются, данные на чужих серверах | Собственный мессенджер на серверах в РК; решения и поручения создаются прямо из сообщений |
| Протоколы и приказы готовятся вручную | Автоматическая сборка документов по шаблонам из решений и поручений |
| Исполнение не контролируется | Реестр поручений, отчёты, приёмка, напоминания, сводка просрочек |

### 1.3. Пользователи

Административно-управленческий персонал центра, руководители подразделений и проектов: до 50 пользователей на старте, с возможностью расширения до 200 без изменения архитектуры.

### 1.4. Термины

| Термин | Значение |
|---|---|
| АУП | Административно-управленческий персонал |
| PWA | Веб-приложение, которое устанавливается на телефон как обычное приложение (иконка, push-уведомления), без App Store и Google Play |
| Решение | Зафиксированное в системе решение, требующее подтверждения адресатов |
| Поручение | Задание с ответственным и сроком, возникшее из протокола, приказа или чата и подлежащее контролю исполнения |
| Протокол | Документ по итогам совещания: повестка, участники, решения, поручения |
| Маршрут согласования | Последовательность или группа согласующих лиц для документа |
| Журнал регистрации | Реестр документов определённого вида со сквозной нумерацией |
| ПДн | Персональные данные |

### 1.5. Нормативная база (Республика Казахстан)

- Закон РК «О персональных данных и их защите» №94-V от 21.05.2013, с изменениями 2024–2026 годов, включая Закон №326-VIII. Действующую редакцию проверить на adilet.zan.kz.
- Закон РК «О языках в Республике Казахстан»: делопроизводство на государственном языке, русский язык употребляется официально наравне с казахским.
- Кодекс РК «О здоровье народа и системе здравоохранения» в части врачебной тайны.
- Закон РК «Об электронном документе и электронной цифровой подписи» №370-II: учитывается для этапа подключения ЭЦП.
- Постановление Правительства РК №832 (Единые требования в области ИКТ и ИБ). Для частного центра не обязательно, используется как ориентир лучших практик.

## 2. Роли и права доступа

Самостоятельной регистрации нет. Учётные записи создаёт администратор, он же выдаёт приглашение по ссылке или QR-коду.

| Роль | Права |
|---|---|
| Администратор | Пользователи, подразделения, роли, справочники, настройки, журнал аудита, импорт из WhatsApp |
| Руководство | Просмотр всех проектов, реестров и панели руководителя; утверждение документов; постановка поручений любому сотруднику |
| Секретарь (делопроизводитель) | Шаблоны документов, журналы регистрации и нумерация, маршруты согласования, регистрация документов, загрузка сканов, контроль сроков поручений |
| Руководитель проекта | Управление своим проектом: команда, роли, % занятости, задачи, этапы, проектный чат, совещания проекта |
| Сотрудник | Чаты, в которых состоит; свои проекты, задачи и поручения; подтверждение решений; согласование назначенных документов; отчёты об исполнении |

Роли совмещаются: один пользователь может быть, например, руководителем проекта и секретарём. Права проверяются на сервере при каждом запросе.

## 3. Функциональные требования

### 3.1. Мессенджер

**Типы чатов:**
- личный (1:1);
- групповой (создаёт любой сотрудник);
- проектный: создаётся автоматически при создании проекта, состав синхронизируется с командой проекта;
- чат совещания (см. 3.5);
- архивный: импортирован из WhatsApp, только чтение (см. 3.9).

**Возможности сообщений:**
- текст, файлы (PDF, DOCX, XLSX и др.), фото, голосовые сообщения;
- ответ с цитатой, пересылка, @упоминание сотрудника и @все;
- отметки «доставлено / прочитано», в групповом чате — список прочитавших;
- редактирование и удаление своего сообщения. Исходная версия сохраняется в журнале аудита, в чате видна отметка «изменено» или «удалено»;
- закрепление сообщений в чате;
- поиск по всем доступным чатам: текст, автор, период, тип вложения;
- статусы «в сети» и «не беспокоить»; отключение уведомлений по чату.

**Интерфейс:** привычный по WhatsApp — список чатов с непрочитанными, лента сообщений, поле ввода с вложениями; основной сценарий — работа с телефона.

**Сценарии приёмки:**
- П-3.1.1. Сотрудник А пишет сотруднику Б. Сообщение появляется у Б меньше чем за 1 секунду, у А видна отметка «прочитано» после открытия чата Б.
- П-3.1.2. Руководитель создаёт проект с 5 участниками. Проектный чат автоматически появляется у всех пятерых. Участник, удалённый из проекта, теряет доступ к чату.
- П-3.1.3. Отредактированное сообщение показывает отметку «изменено», исходный текст доступен администратору в журнале аудита.

### 3.2. Действия над сообщениями

Долгое нажатие (или меню) на любом сообщении предлагает:

| Действие | Результат | Обязательные поля |
|---|---|---|
| **Создать задачу** | Задача, связанная с сообщением и чатом | Ответственный (ровно один), срок |
| **Зафиксировать решение** | Решение с запросом подтверждения | Формулировка, адресаты, срок ответа |
| **Создать поручение** | Поручение на контроле исполнения | Формулировка, ответственный, срок |
| **Добавить в протокол** | Пункт протокола текущего или выбранного совещания | Тип пункта (решение или поручение) |

**Решение с подтверждением:**
- адресаты видят карточку решения в чате с кнопками «Согласен», «Возражаю» (комментарий обязателен) и «Ознакомлен»;
- автор и все участники видят счётчик «ответили 3 из 5» и список ответов;
- неответившим приходят напоминания: при приближении срока и в момент его наступления;
- итоговый статус: «принято» (все согласны или ознакомлены), «есть возражения», «просрочено»;
- решение попадает в реестр решений и может быть включено в протокол или приказ.

Из карточки задачи, решения или поручения можно перейти к исходному сообщению и обсуждению, и наоборот.

**Сценарии приёмки:**
- П-3.2.1. Из сообщения в групповом чате создаётся решение для 3 адресатов. Двое нажимают «Согласен», третий — «Возражаю» с комментарием. Статус «есть возражения», автор видит комментарий.
- П-3.2.2. Из сообщения создаётся задача без ответственного — система не даёт её сохранить.

### 3.3. Проекты

**Карточка проекта:** название, цель, ожидаемый результат, статус (идея → в работе → приостановлен → завершён → отменён), даты начала и окончания, приоритет, куратор (из руководства), руководитель проекта, подразделение-инициатор.

**Команда проекта:** участник, роль в проекте (руководитель, ответственный за направление, исполнитель, консультант, наблюдатель) и % занятости.

**Этапы и вехи:** название, срок, ответственный, статус. Просроченные вехи подсвечиваются.

**Задачи проекта:** список и канбан-доска. Фильтры: «мои», «просроченные», «без движения больше N дней».

**Документы проекта:** файлы, протоколы совещаний проекта, связанные приказы.

**Лента событий проекта:** изменения статусов, новые задачи, решения, документы.

**Сценарии приёмки:**
- П-3.3.1. Руководитель проекта добавляет этап со сроком в прошлом — этап отображается как просроченный в карточке и на панели руководителя.

### 3.4. Ответственность и загрузка

- **Матрица «сотрудник × проект»**: строки — сотрудники, столбцы — проекты, в ячейке роль и % занятости. Фильтр по подразделению и статусу проекта.
- **Профиль загрузки сотрудника**: все проекты с ролями, открытые задачи и поручения, просрочки. Предупреждение, если суммарная занятость больше 100%.
- **Поиск «кто отвечает за…»**: по названию проекта, задачи, поручения или направления — ответственный и его контакты.
- **Контрольные списки**: проекты без руководителя, задачи и поручения без движения, просроченные.

**Сценарии приёмки:**
- П-3.4.1. Сотрудник занят в трёх проектах на 50%, 40% и 30%. В профиле и матрице видно предупреждение о загрузке 120%.

### 3.5. Совещания и протоколы

**Совещание** создаётся из проекта, чата или раздела «Совещания»: тема, дата и время, место или ссылка, председатель, секретарь, участники, повестка (пункты).

- У каждого совещания есть свой чат. Участники получают приглашение и напоминание.
- Во время или после совещания секретарь отмечает по пунктам повестки: «слушали», «решили» (решения) и «поручить» (поручения с ответственным и сроком). Пункты можно создавать и из сообщений (см. 3.2).
- По кнопке **«Сформировать протокол»** система собирает документ DOCX и PDF по шаблону: номер, дата, участники, повестка, решения, поручения. Язык — русский, казахский или оба.
- Протокол проходит согласование (см. 3.6) и регистрацию в журнале протоколов с присвоением номера.
- После регистрации поручения из протокола автоматически попадают в контроль исполнения (см. 3.7) и уведомляют ответственных.

**Сценарии приёмки:**
- П-3.5.1. Совещание с 3 пунктами повестки, 2 решениями и 3 поручениями. Сформированный протокол DOCX содержит все пункты и открывается в Microsoft Word без ошибок. После регистрации протокол получает номер, 3 поручения появляются у ответственных.

### 3.6. Приказы и формальные документы

**Виды документов** (справочник, пополняемый секретарём): приказ по основной деятельности, протокол, служебная записка, распоряжение и др.

**Шаблоны:**
- шаблон — файл DOCX с полями подстановки (дата, номер, преамбула, пункты, исполнители, сроки, согласующие); секретарь редактирует его в Microsoft Word и загружает в систему;
- у шаблона могут быть версии на русском и казахском языках;
- в комплекте поставляются базовые шаблоны протокола, приказа и служебной записки, адаптированные под форму центра на этапе 0.

**Жизненный цикл документа:**
`черновик → на согласовании → (возвращён на доработку) → согласован → подписан (загружен скан) → зарегистрирован → на исполнении → исполнен / снят с контроля`

- Черновик создаётся из шаблона: вручную, из решения или из протокола.
- **Маршрут согласования** — последовательный, параллельный или смешанный. Согласующий нажимает «Согласовать» или «Вернуть с замечаниями» (комментарий обязателен). Все действия попадают в лист согласования с датой и временем.
- **Подписание** на первой очереди бумажное: печать итогового PDF, подпись руководителя, загрузка скана. Архитектура предусматривает последующее подключение ЭЦП (см. 5.6).
- **Регистрация**: номер присваивается автоматически по журналу данного вида документов (формат номера настраивается, например `ПР-2026/015`), номера уникальны и не повторяются.
- Пункты приказа с исполнителями и сроками становятся поручениями (см. 3.7).

**Сценарии приёмки:**
- П-3.6.1. Секретарь создаёт приказ из шаблона, задаёт маршрут «юрист → главный бухгалтер (параллельно) → директор». Юрист возвращает с замечаниями. После исправления документ согласован всеми, лист согласования отражает всю историю.
- П-3.6.2. Два приказа, зарегистрированные подряд, получают последовательные номера; повторная регистрация невозможна.

### 3.7. Контроль исполнения

- **Реестр поручений** собирает поручения из протоколов, приказов и чатов: источник, формулировка, ответственный, соисполнители, контролёр, срок, статус.
- Статусы: «новое → в работе → на проверке → исполнено», «возвращено на доработку», «просрочено», «снято с контроля» (с указанием основания).
- **Отчёт об исполнении**: ответственный пишет текст и прикладывает файлы, контролёр принимает его или возвращает с комментарием.
- **Перенос срока** — по запросу ответственного с обоснованием и согласием контролёра; история переносов сохраняется.
- Напоминания: за 3 дня и за 1 день до срока, в день срока, после просрочки ежедневно. Сроки напоминаний настраиваются.
- Еженедельная сводка просрочек руководству (в приложении).

**Сценарии приёмки:**
- П-3.7.1. Сквозной сценарий: сообщение в чате → решение → подтверждения 3 из 3 → включение в протокол → протокол сформирован, согласован и зарегистрирован → поручение у ответственного → отчёт → приёмка контролёром → статус «исполнено».

### 3.8. Уведомления

- Каналы первой версии: **внутри приложения** (счётчики непрочитанного, всплывающие уведомления, звук) и **Web Push** на телефон и компьютер. E-mail-сводки и SMS в первую версию не входят; к ним вернёмся по итогам пилота, если у части сотрудников Web Push будет работать нестабильно.
- События: новое сообщение и упоминание, новая задача или поручение, запрос подтверждения или согласования, приближение и наступление срока, возврат документа, приёмка отчёта.
- **Push содержит минимум данных**: «Новое сообщение от Иванова А.», «Вам направлен документ на согласование» — без текста сообщений и документов, потому что push доставляется через системные сервисы Google и Apple.
- Настройки пользователя: отключение по чату, «только упоминания», тихие часы.

**Сценарии приёмки:**
- П-3.8.1. На Android-телефоне и на iPhone (iOS 16.4+, приложение установлено на экран «Домой») при закрытом приложении приходит push о новом сообщении; нажатие открывает нужный чат.

### 3.9. Переход с WhatsApp

- **Импорт истории**: администратор загружает экспорт группы WhatsApp (.zip с файлом `.txt` и медиа, функция «Экспорт чата» в WhatsApp). Система разбирает формат (даты, авторы, сообщения, вложения), предлагает сопоставить авторов с пользователями системы и создаёт архивный чат только для чтения с поиском.
- **Подключение сотрудников**: приглашение по ссылке или QR-коду; при первом входе — смена пароля и согласие на обработку ПДн.
- **Инструкция по установке** в самом приложении: пошагово для Android (Chrome) и iPhone (Safari → «На экран Домой»).
- **Регламент перехода**: параллельная работа 2–4 недели. Затем рабочие группы WhatsApp закрываются, официальные решения и поручения принимаются только в системе.

**Сценарии приёмки:**
- П-3.9.1. Экспорт реальной группы WhatsApp (не менее 1000 сообщений с фото) импортирован; авторы сопоставлены; поиск находит сообщение по слову; медиа открываются.

### 3.10. Панель руководителя

- Проекты по статусам; проекты с просроченными вехами.
- Поручения: всего, на исполнении, просрочено (по подразделениям и сотрудникам).
- Решения без ответа.
- Документы на согласовании дольше N дней.
- Перегруженные сотрудники (занятость > 100%).
- Из каждого показателя можно перейти к списку объектов.

### 3.11. Журнал аудита

- Фиксируются: входы и выходы, неудачные попытки входа, создание, изменение и удаление объектов, редактирование и удаление сообщений (с исходной версией), смена статусов, согласования, регистрация документов, изменения прав, импорт и экспорт.
- Записи только добавляются, изменить или удалить их средствами приложения невозможно.
- Просмотр и выгрузка — администратору; фильтр по пользователю, объекту, периоду.

### 3.12. Администрирование

- Пользователи: создание, блокировка, сброс пароля, роли, подразделение и должность.
- Справочники: подразделения, должности, виды документов, журналы регистрации, роли в проекте.
- Настройки: формат номеров, сроки напоминаний, срок хранения сообщений и файлов, тихие часы по умолчанию.

## 4. Нефункциональные требования

### 4.1. Размещение и персональные данные

- Все данные, резервные копии и журналы хранятся **только на серверах в Республике Казахстан** (сервер центра или облако в РК) — Закон №94-V, ст. 12.
- Внешние SaaS-сервисы для хранения и обработки содержимого не используются. Исключение — системные push-сервисы браузеров, через которые передаются только уведомления без содержимого.
- Письменное согласие сотрудников на обработку ПДн; уведомление уполномоченного органа о начале обработки (если требуется действующей редакцией закона).
- Функции удаления и обезличивания ПДн уволенного сотрудника с сохранением целостности документов.
- Регламент реагирования на утечку: уведомление уполномоченного органа в течение 1 рабочего дня.
- **Данные пациентов** в чатах и документах системы не передаются. Об этом говорят предупреждение в интерфейсе (при первом входе и в подсказке поля ввода) и регламент. Система предназначена для административной работы.

### 4.2. Информационная безопасность

- Доступ только по HTTPS (TLS 1.2+).
- Вход по логину и паролю; политика сложности паролей; блокировка после 5 неудачных попыток; вторая ступень (TOTP) — по желанию пользователя, обязательна для администраторов.
- Сессии с ограниченным сроком жизни; выход на всех устройствах.
- Права проверяются на сервере; файлы выдаются только по проверке прав.
- Шифрование резервных копий.
- Обновления безопасности компонентов — не реже раза в месяц.

### 4.3. Надёжность и резервное копирование

- Ежедневное резервное копирование БД и файлов; хранение 30 дней; ежемесячная проверка восстановления.
- Целевая доступность — 99% в рабочее время.
- Восстановление после сбоя — не дольше 4 часов.

### 4.4. Производительность

- 50 одновременных пользователей (с запасом до 200 без изменения архитектуры).
- Доставка сообщения — менее 1 секунды.
- Открытие экранов — менее 2 секунд на мобильном интернете 4G.

### 4.5. Удобство

- Интерфейс ориентирован на телефон, адаптируется под планшет и компьютер.
- Поддержка: Android 9+ (Chrome), iOS 16.4+ (Safari), актуальные Chrome, Edge, Firefox, Safari на компьютере.
- Интерфейс полностью на **казахском и русском**, язык выбирает пользователь.
- Новый сотрудник осваивает отправку сообщений и подтверждение решений без обучения, остальные функции — после 30-минутного инструктажа.

### 4.6. Переносимость

- Вся система разворачивается одной командой `docker compose up` на любом сервере Linux.
- Требования к серверу на 50 пользователей: 4 vCPU, 8 ГБ ОЗУ, 200 ГБ SSD (уточняется на пилоте).

## 5. Архитектура и технологии

### 5.1. Компоненты

| Компонент | Технология | Назначение |
|---|---|---|
| Веб-приложение (PWA) | Next.js + TypeScript, Tailwind CSS, service worker, i18n (kk/ru) | Интерфейс для телефона и компьютера, установка на телефон, Web Push |
| API-сервер | NestJS + TypeScript, REST + WebSocket (Socket.IO), Prisma ORM | Бизнес-логика, права, чат в реальном времени, планировщик напоминаний |
| База данных | PostgreSQL | Основные данные, полнотекстовый поиск по-русски и по-казахски |
| Файловое хранилище | Отдельный том на диске сервера (решение заказчика) | Вложения, документы, сканы, импорт WhatsApp. Файлы отдаёт только API после проверки прав. Хранилище скрыто за интерфейсом, чтобы при росте объёма можно было перейти на S3-совместимое без переписывания кода. Том входит в ежедневный бэкап |
| Генерация документов | docxtemplater (core, MIT) | Заполнение DOCX-шаблонов |
| Конвертация в PDF | Gotenberg (MIT, LibreOffice внутри) | DOCX → PDF |
| Обратный прокси | Caddy | HTTPS, автоматические сертификаты |
| Развёртывание | Docker Compose | Перенос между сервером центра и облаком в РК |

Обоснование выбора и сравнение с готовыми продуктами — в `docs/research.md`.

### 5.2. Структура репозитория

```
apps/web        — PWA (Next.js)
apps/api        — API-сервер (NestJS)
packages/shared — общие типы, схемы валидации, статусы
infra/          — docker-compose, Caddyfile, скрипты бэкапа
templates/      — базовые DOCX-шаблоны документов
docs/           — ТЗ, исследование, дорожная карта
```

### 5.3. Основные сущности

`User`, `Department`, `Position`, `Role` · `Project`, `ProjectMember` (роль, % занятости), `Milestone` · `Chat`, `ChatMember`, `Message`, `MessageRead`, `Attachment` · `Task` · `Decision`, `DecisionResponse` · `Meeting`, `AgendaItem` · `DocumentType`, `DocumentTemplate`, `Document` (протокол, приказ и др.), `ApprovalRoute`, `ApprovalStep`, `RegistryJournal` · `Assignment` (поручение), `ExecutionReport`, `DeadlineChange` · `Notification`, `PushSubscription` · `AuditLog`.

Задача, решение и поручение хранят ссылку на исходное сообщение и чат.

### 5.4. Реальное время и уведомления

WebSocket-соединение для чатов и счётчиков. Web Push (VAPID-ключи генерируются на своём сервере) для закрытого приложения. Планировщик в API-сервере рассылает напоминания о сроках.

### 5.5. Интеграционный слой

Все функции доступны через документированный REST API (OpenAPI). Это нужно для будущих интеграций (СЭД, 1С, кадровая система) и ИИ-помощников.

### 5.6. Задел для ЭЦП (вторая очередь)

- Подписание в браузере через NCALayer (клиент `ncalayer-js-client`), проверка подписи на сервере через NCANode (Docker, требует лицензионные библиотеки Kalkan НУЦ РК).
- Опционально — подписание с телефона по QR через eGov mobile (коммерческий сервис SIGEX).
- Уже на первой очереди документ хранит неизменяемую PDF-версию и её хэш, к которым в дальнейшем прикрепляется подпись.
